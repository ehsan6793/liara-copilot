# همکار فنی لیارا (Liara Copilot)

دستیار هوشمندی که نقش یک همکار فنی DevOps را برای صاحب یک اپ روی لیارا بازی می‌کند:
می‌پرسی «چرا سایتم ارور می‌ده؟» یا «چرا کند شده؟»، دستیار لاگ و متریک واقعی اپ را از
API رسمی لیارا می‌خواند، علت‌های محتمل را اولویت‌بندی می‌کند، راه‌حل پیشنهاد می‌دهد و
فقط با **تأیید صریح خودت** اقدام اصلاحی (ری‌استارت، تغییر env) را روی سرویس واقعی اجرا
می‌کند — و بعد نتیجه را با گرفتن لاگ تازه، خودش راستی‌آزمایی می‌کند.

ساخته‌شده برای چالش «همکار فنی هوشمند لیارا» — هکاتون Agentic AI استارکوچ.

## ویژگی‌های کلیدی

- **اتصال واقعی به API لیارا** (نه شبیه‌سازی‌شده): لیست اپ‌ها، لاگ، رویداد، متریک CPU/RAM، ری‌استارت، تنظیم env.
- **عیب‌یابی هوشمند قاعده‌محور**: تحلیل لاگ با الگوهای خطای واقعی (کمبود حافظه، قطع اتصال دیتابیس، متغیر محیطی نبود، کرش، تایم‌اوت، ...) و اولویت‌بندی علت‌های محتمل با درصد اطمینان.
- **Human-in-the-loop واقعی**: عملیات فقط‌خواندنی (لاگ/وضعیت/متریک) بی‌درنگ اجرا می‌شود؛ عملیات حساس (ری‌استارت، تغییر env، روشن/خاموش) تا تأیید صریح کاربر در صف می‌ماند و اجرا نمی‌شود.
- **راستی‌آزمایی خودکار نتیجه**: بعد از هر اقدام اصلاحی، دستیار خودش لاگ تازه می‌گیرد و می‌گوید مشکل واقعاً برطرف شده یا نه.
- **گفتگوی فارسی و رابط ساده**: کاربر با حداقل دانش فنی، با جمله‌ی عادی («چرا کند شده؟») کار را پیش می‌برد.

## سناریوی واقعیِ دمو

یک اپ نمونه (`demo/broken-app`) روی لیارا دیپلوی شده که وقتی `DB_HOST` تنظیم نشده
باشد، روی هر درخواست خطای ۵۰۰ می‌دهد — دقیقا شبیه باگ رایج «یادم رفت env رو بعد از
دیپلوی ست کنم»:

1. کاربر: «چرا سایتم ارور می‌ده؟»
2. دستیار لاگ ۱ ساعت اخیر + رویدادها + متریک CPU/RAM را از API لیارا می‌گیرد.
3. تحلیل قاعده‌محور تشخیص می‌دهد: علت محتمل‌ترین «متغیر محیطی لازم تنظیم نشده» (اطمینان ~۹۱٪).
4. دستیار پیشنهاد می‌دهد و از کاربر مقدار درست را می‌پرسد.
5. کاربر: «env رو DB_HOST=prod-db.internal کن» → دستیار قبل از اجرا تأیید می‌خواهد.
6. کاربر تأیید می‌کند → دستیار از API لیارا `update-envs` را صدا می‌زند.
7. دستیار خودش دوباره لاگ تازه می‌گیرد و تأیید می‌کند که خطا دیگر تکرار نمی‌شود.

این مسیر کامل در `tests/test_agent_scenario.py` هم به‌صورت خودکار (با یک کلاینت جعلی
با ساختار دقیقاً مطابق پاسخ واقعی API لیارا) تست و لاگ‌گذاری شده است.

## معماری

```
کاربر ⇄ چت (Vanilla JS, static/) ⇄ FastAPI (app/main.py)
                                       │
                                  Agent (app/agent.py)
                               NLU قاعده‌محور + تشخیص نیت
                                       │
                         ┌─────────────┴─────────────┐
                    ابزارهای safe                ابزارهای risky
              (list/status/logs/metrics)     (restart/set-env/power)
                    بی‌درنگ اجرا می‌شوند          در صف PENDING می‌مانند
                                       │             تا تأیید کاربر (/api/confirm)
                              app/tools.py: diagnose()
                           الگوهای خطا + آستانهٔ CPU/RAM
                                       │
                              app/liara_client.py
                         httpx ⇄ api.liara.ir / api.iran.liara.ir
```

- **بدون build**، بدون فریم‌ورک فرانت؛ UI با Vanilla JS و یک فایل CSS.
- **بدون وابستگی به LLM**: تشخیص نیت و عیب‌یابی قاعده‌محور است و همیشه کار می‌کند. (در صورت نیاز می‌توان لایه‌ی LLM tool-calling اختیاری — مثل دستیار گفتگویی ترب‌گرد — روی همین ابزارها اضافه کرد؛ `.env.example` جای کلید آن را از قبل نگه داشته است.)
- **ریسک‌بندی ابزار**، نه مسیر: هر ابزار (`app/tools.py`) برچسب `safe`/`risky` دارد، نه هر intent؛ این یعنی هیچ اقدام تغییردهنده‌ای بدون عبور از لایه‌ی تأیید اجرا نمی‌شود، حتی اگر مسیر تشخیص نیت اشتباه کند.

## نحوه‌ی اتصال به APIهای لیارا

طبق مستندات رسمی (`developers.liara.ir`):

| قابلیت | متد | Endpoint |
|---|---|---|
| لیست اپ‌ها | GET | `https://api.liara.ir/v1/projects` |
| وضعیت یک اپ | — | از همان لیست فیلتر می‌شود |
| لاگ‌ها | GET | `https://api.iran.liara.ir/v1/projects/{name}/logs?since=...` |
| رویدادها | GET | `https://api.liara.ir/v1/projects/{name}/events` |
| متریک CPU/RAM/دیسک | GET | `https://api.liara.ir/v1/projects/{name}/metrics/summary` |
| ری‌استارت | POST | `https://api.liara.ir/v1/projects/{name}/actions/restart` |
| روشن/خاموش | POST | `https://api.liara.ir/v1/projects/{name}/actions/{on|off}` |
| تنظیم env | POST | `https://api.liara.ir/v1/projects/update-envs` |

احراز هویت با هدر `Authorization: Bearer <LIARA_API_TOKEN>` — توکن از
کنسول لیارا (حساب کاربری ← API Token) ساخته می‌شود و فقط در فایل `.env`
(gitignore شده) نگه داشته می‌شود؛ هیچ‌جا commit یا در کد hardcode نشده است.

## محدودیت‌های راهکار (طبق خود چالش، باید صریح اعلام شود)

- **دیپلوی اولیهٔ سورس‌کد از طریق API پیچیده‌تر از محدودهٔ این MVP بود** (نیاز به
  پکیج‌کردن و آپلود tar/ایمیج از طریق چند endpoint جداگانه). راهکار فعلی روی
  **مدیریت/پایش/عیب‌یابی اپی که از قبل دیپلوی شده** تمرکز کرده — دقیقاً بخشی از
  چرخه‌ی عمر که صورت‌مسئله اجازه داده («بخش مشخصی از چرخه را پوشش دهید»). اولین
  دیپلوی را فعلاً باید با CLI لیارا (`liara deploy`) یا پنل انجام دهید؛ از آن به بعد
  دستیار کار را دست می‌گیرد.
- **تنظیم دامنه/ایرنیک پیاده‌سازی نشده** — API لیارا برای دامنه وجود دارد اما در این
  نسخه فقط مسیرهای مانیتورینگ/عیب‌یابی/env پیاده شده‌اند؛ این محدودیت در خود پاسخ
  دستیار هم صادقانه اعلام می‌شود اگر کاربر دامنه بخواهد.
- **متریک‌های per-process یا I/O دیسک دقیق از API در دسترس نیست**؛ فقط خلاصهٔ
  CPU/RAM/دیسک همان چیزی است که `metrics/summary` برمی‌گرداند — همان را نشان می‌دهیم،
  چیزی را شبیه‌سازی یا تخمین نمی‌زنیم.
- عیب‌یابی قاعده‌محور است، نه یک مدل یادگیری‌شده؛ روی الگوهای متن لاگ و آستانه‌ی
  مصرف منابع کار می‌کند — برای اغلب خطاهای رایج (کرش، env گم‌شده، اتصال دیتابیس،
  کمبود حافظه، تایم‌اوت) دقیق است، ولی علت‌های کاملاً جدید را فقط به‌عنوان لاگ خام
  نشان می‌دهد، تشخیص نمی‌دهد.

## نحوه‌ی تعامل کاربر با سیستم

۱. کاربر وارد صفحه‌ی چت می‌شود و اپی را که دستیار پیدا کرده انتخاب می‌کند (یا دستیار
   خودش وقتی فقط یک اپ هست، آن را انتخاب می‌کند).
۲. سؤال را با زبان طبیعی فارسی می‌پرسد: «وضعیت چطوره»، «لاگ‌ها رو نشون بده»، «منابع
   چطوره»، «چرا ارور می‌ده»، «ری‌استارت کن»، «env رو KEY=VALUE کن».
۳. برای عملیات فقط‌خواندنی، پاسخ و کارت‌های داده (لاگ، وضعیت، نمودار CPU/RAM، لیست
   علل) فوراً نمایش داده می‌شود.
۴. برای عملیات حساس، یک نوار زرد پایین صفحه ظاهر می‌شود با توضیح دقیق اقدام و دو
   دکمه «تأیید و اجرا» / «لغو». تا کاربر کلیک نکند، هیچ تغییری روی سرویس واقعی لیارا
   اعمال نمی‌شود.
۵. بعد از اجرا، نتیجه و لاگ تازه نمایش داده می‌شود تا کاربر خودش هم ببیند مشکل واقعاً
   حل شده یا نه.

## اجرا

### ویندوز
`1_setup.bat` → مقدار `LIARA_API_TOKEN` را در `.env` بگذار → `2_run.bat`

### macOS / Linux
```bash
pip install -r requirements.txt
cp .env.example .env   # و LIARA_API_TOKEN را بگذار
bash run.sh            # http://localhost:8010
python tests/test_agent_scenario.py   # تست کامل سناریو بدون نیاز به توکن واقعی
```

## دیپلوی روی لیارا

```bash
liara deploy --platform docker --port 8010
liara env set LIARA_API_TOKEN=... -a liara-copilot
```
